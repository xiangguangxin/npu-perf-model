# MVP-5：解析验证与架构实验设计

## 1. 目标与范围

目标是让现有 SystemC NPU 性能模型具备独立验证、可复现实验和可解释的架构结论，服务于 NPU/GPU 性能建模与架构探索方向的项目展示。

首版完成：

1. 独立解析对账：请求数、HBM 流量、有效/执行运算量、PE 时间和受控串行总时间。
2. 架构实验：调度模式对比、互连带宽扫描、阵列规模扫描及 Roofline 分析。
3. 一份可复现报告：配置、数据、图表、验证结果、异常解释和适用边界。

首版不要求外部模拟器或真实芯片校准，不新增自适应 tiling、HBM bank 模型或完整周期级 PE 模型。结论限定为“实现符合声明的建模假设”，不声称已证明真实 NPU 性能预测精度。

本文保留实施前的设计与验收约定。首版现已实现，实测结果和适用边界见 [实验报告](../experiments/MVP5_Results.md)。

## 2. 当前实现与实验前提

依据 `src/workload_driver.cpp`、`src/pe_array.cpp`、`src/interconnect.cpp`、`src/memory_controller.cpp` 和 `src/perf_monitor.cpp`：

| 当前行为 | 实验含义 |
|---|---|
| tile 边长固定等于阵列边长 a | 改变阵列同时改变 tiling、请求大小与流量 |
| 每个 K-slice 重读两个完整输入 tile，输出 tile 最后写回一次 | 不存在跨输出 tile 的输入驻留复用 |
| 边界也执行和传输完整 tile | 必须区分有效运算和补齐后的执行运算 |
| 每次 PE pass 固定 3a 周期、记账 a³ MAC | 执行吞吐计算天花板为标称峰值的 1/3 |
| 串行模式依次加载两个输入；双缓冲模式并发提交两个输入 | 两模式对比同时包含输入并发和计算/加载重叠收益 |
| loader 每轮提交两个请求后等待，compute 还可能提交输出写回 | DMA channel 增加不等于独立请求源持续增加 |
| IC 在发出请求时预约下一次可发出时间，立即向下游转发 | IC 带宽是请求发出间隔约束，不是每笔响应前额外累加的服务时间 |
| MC 在 HBM 数据就绪后串行化传输，HBM 固定延迟可以重叠 | 不能把所有请求延迟之和当作并发时间下界 |
| Buffer allocate 没有强制容量检查，调度占位也未完整表示两操作数和输出 | 容量实验不能声称已验证真实 SRAM 容量约束 |
| Buffer access_time 是调用方等待，未建立统一共享端口调度 | 不以模型验证 SRAM 端口竞争或完整 SRAM Roofline |
| 默认每元素 1 Byte，报告当前使用 FLOP 标签 | 新指标使用 OP/s、OP/Byte，约定 1 MAC = 2 OP |

首版固定现有核心时序语义。验证暴露的问题单独修复并重新建立基线；不要调整解析参数去掩盖模型问题。

## 3. 数据与结果接口

### 3.1 结构化输出

新增可选 JSON 结果文件参数 `--output-json PATH`，保留现有终端输出。避免依赖当前仅三位小数的显示值做时间精度校验。

每次运行记录：

- schema_version、run_id、源码 commit、工作区是否有修改、完整命令。
- M/K/N、array_n、buffer_kb、data_bytes、时钟频率。
- 调度模式、DMA 数和 outstanding 上限、仲裁策略、队列深度。
- HBM 带宽与延迟、IC 带宽与延迟、Buffer 带宽。
- SystemC 时间分辨率、仿真时间整数 ticks。
- 请求数、HBM 字节数、PE passes、MAC 数。
- useful_ops、executed_ops、对应吞吐和 AI。
- 队列平均等待、queue_full 次数、累计背压时间、各源授予数。

派生数据统一由整数计数和精确时间计算，不重复使用格式化后的浮点文本。固定工作量全部完成后的授予数不作为仲裁公平性的充分证据。

## 4. 独立解析验证

### 4.1 记号与精确计数

设阵列边长 a，数据宽度 d Byte，时钟 f Hz：

```text
mt = ceil(M/a), nt = ceil(N/a), kt = ceil(K/a)
O  = mt * nt                     # 输出 tile 数
P  = O * kt                      # PE pass 数
S  = a*a*d                       # 每请求字节数
R  = O * (2*kt + 1)              # 两次输入读取 + 一次输出写回
Q  = R * S
F_useful   = 2*M*K*N
F_executed = 2*P*a*a*a
T_PE       = P * 3*a/f
```

独立脚本仅输入硬件配置与 workload，输出上述参考量。不得读取仿真报告中的 bytes/passes 再把它们当作期望值，也不链接生产计算函数。

检查 `MC 请求数 = IC 请求数 = R`、`MC 字节数 = Q`、PE 计数准确。条件允许时补充 DMA 总计数交叉核对。

### 4.2 串行总时间的精确参考

首版精确时间用例限制：单 DMA、串行模式、无其他流量、IC 带宽不低于 HBM 带宽、当前立即完成响应握手语义。此时相邻请求间隔足以释放 IC 预约，不产生 IC 等待。

```text
T_req = L_noc/f + L_hbm/f + quantize(S/B_hbm)
T_buf = ceil(S/buf_bw_Bpc)/f
T_serial = R * (T_req + T_buf) + P * 3*a/f
```

带宽使用 Byte/s；`quantize` 按配置的 SystemC 时间分辨率处理。不要额外加入 `S/B_ic`：当前 IC 是发出间隔模型，不是先传完再转发。

手算锚点：M=K=N=a=16、d=1、f=1 GHz、HBM=IC=256 GB/s、HBM 延迟=100 cycle、NoC 延迟=0、Buffer=64 Byte/cycle：

```text
P=1, R=3, S=256 B, Q=768 B
F_useful=F_executed=8192 OP
T_req=101 ns, T_buf=4 ns, T_PE=48 ns
T_serial=3*(101+4)+48=363 ns
```

这是待验证的独立期望值，不是已运行的实测结果。若结果不同，先检查时序、配置或实现偏差，不修改期望值去迁就输出。

### 4.3 并发模式验证

不使用 `max(总计算时间, 总访存时间)` 作为双缓冲总时间的精确答案。它遗漏首尾、有限槽位、输出写回和共享资源竞争。

首版对并发模式验证：

- 相同 workload/config 下，请求数、流量和运算数与串行一致。
- 总时间不小于 PE 累计时间，也不小于 Q/B_hbm。
- 模型执行吞吐不超过 `2*a²*f/3`。
- 相同输入重复运行计数和仿真时间一致。
- 超时、协议错误、死锁和未完成任务均判失败。

IC 仅限制发出间隔，有限请求批次不能机械使用 Q/B_ic 作为严格时间下界；请求大小固定时，发出 R 笔请求至少跨越约 `(R-1)*S/B_ic`，还需结合最后请求完成时间。最终报告区分稳态 IC 带宽参照和有限批次边界。

### 4.4 用例与误差门槛

| 用例组 | 参数 | 验证目标 |
|---|---|---|
| 单 tile | 16,16,16；a=16 | 手算锚点 |
| 多 tile | 32,32,32；64,128,64；a=16 | 循环与输出写回计数 |
| 边界 | 1,1,1；17,17,17；31,33,65；a=16 | 补齐流量和有效运算 |
| 阵列 | 64,64,64；a=8/16/32 | 参数变化后的计数与时间 |
| NoC | 单 tile，延迟=0/2/10 cycle | 串行每笔延迟累加 |
| 并发 | 上述典型 workload，默认双缓冲 | 守恒、时间下界、确定性 |

整数计数要求完全相等。整周期、精确可表示的串行锚点时间要求整数 ticks 一致；非整周期用例按逐项舍入推导误差预算，最多允许每个被量化时长 1 tick 的累计误差，并输出预算来源。不设置任意的“误差小于 5% 就算通过”。

## 5. 实验矩阵

所有矩阵均采用十进制 GB/s；buffer_kb 沿用程序的容量换算。除扫描项外保留固定配置，并完整保存实际配置。

### E1：调度与预取收益

workload：32³、128³、512³；a=16，Buffer=256 KB，DMA=1，FIFO，IC=HBM=256 GB/s。

首版比较 `--serial` 与默认双缓冲，报告 T、Q、OP/s 和 `T_serial/T_double`，名称为“调度模式综合收益”，不能称为纯重叠收益。

为支持机制归因，随后增加一个受控中间模式 `paired`：每个 K-slice 并发读取两个输入，完成 Buffer 等待后计算，但不预取下一 slice。与现有串行、双缓冲一起构成：

| 模式 | 两个输入请求并发 | 跨 slice 预取/计算重叠 |
|---|---|---|
| serial | 否 | 否 |
| paired（新增） | 是 | 否 |
| double | 是 | 是 |

建议新增 `--schedule serial|paired|double`，保留 `--serial` 兼容；冲突参数报错。paired 的请求数、运算、Buffer 等待与原模式相同，仅改变调度。正式报告必须完成该对照，才能分别讨论输入并发与跨 slice 重叠收益；两个加速比不是可相加的百分比。

### E2：互连带宽与平台期

M=K=N=128，a=16，Buffer=256 KB，DMA=1，FIFO，默认双缓冲；扫描 IC=8/16/32/64/128/256 GB/s，共 6 点。

输出带宽—吞吐、带宽—总时间，以及排队等待。核对 Q 和执行运算不变。平台期可能来自 HBM 延迟、有限请求供应、PE 时间或其他等待，不能仅凭平台期宣布 compute-bound。

用 E1 的调度对照及 PE 时间下界辅助解释；无法归因时明确保留不确定性，下一步再增加等待原因统计。首版不要求新增 HBM 带宽、延迟和 outstanding CLI 扫描。

### E3：阵列与分块的联合变化

workload=32³、128³；a=8/16/32；IC=32/256 GB/s，其余固定，共 12 点。

输出 useful OP/s、executed OP/s、利用率、Q 和 passes。解释收益来自 PE 数、请求大小、复用/分块或开销中的哪些变化。该实验不能称为“其他条件完全不变的纯 PE 扩容”。

### E4：Roofline 定位

固定 a=16，M=N=128，K=16/32/128/512；分别在 IC=16 和 256 GB/s 下运行，其余默认，共 8 点，每种硬件带宽单独画屋顶。

当前完整 tile 的执行强度为：

```text
I_executed = 2*a*kt / (d*(2*kt+1))
```

因此该模型不能仅靠增加 M/N 扫出宽范围 AI。横轴用实际 Q，不用理想最小流量。画标称峰值 `2*a²*f`、PE 天花板 `2*a²*f/3` 和稳态带宽参照 `min(B_ic,B_hbm)*I`，注明 IC 有限批次语义。

对齐 workload 主图使用 OP/s 与 OP/Byte；边界案例另图区分有效与执行指标。屋顶差距是分析线索，不是模型误差百分比。

### E5：Buffer 行为基线

M=K=N=128，a=16；Buffer=4/16/64/256 KB，其余默认，共 4 点。

当前固定调度预期 Q 和时间不随容量变化。检查这一行为并解释缺失的容量驱动分块机制，不宣称验证了“更大 SRAM 提升复用”。完整容量约束与驻留策略列为后续扩展。

DMA 数量及仲裁公平性不列入首版主要结论。若后续研究竞争，需独立持续流量源，统计服务率和等待分布；不能用均匀分发的有限 GEMM 请求证明公平性。

## 6. 实施顺序与验收

| 步骤 | 修改与交付 | 通过条件 |
|---|---|---|
| A：冻结基线 | 保存源码版本、构建配置；运行已有 CTest | 已有测试通过，修改工作区可追溯 |
| B：结构化统计 | JSON 输出、有效/执行计数、ticks | 字段完整；报告和整数计数一致 |
| C：独立参考 | Python 公式、验证脚本与微小手算案例 | 全部计数与串行精确时间通过 |
| D：实验运行 | 批量脚本、E1–E5 数据；paired 调度及对照 | 超时/错误显式失败；完整配置可重跑 |
| E：分析交付 | 图表、报告、最小复现命令 | 每项结论有数据与条件，局限明确 |

新增 paired 模式应测试其计数守恒、单 slice 无跨 slice 重叠、多个 slice 的预期时序，以及原 serial/double 行为未回归。独立解析脚本用上述手算常量校验，避免同一实现同时生成期望和实际值。

统计属于确定性仿真结果，不以宿主机进程运行耗时替代仿真时间；选取代表案例重复运行两次检查确定性，不做无意义的大量重复取平均。若新增随机模型，再引入随机种子和分布统计。

## 7. 报告模板与完成标准

每组实验按“问题 → 固定量/扫描量 → 数据与图 → 解释 → 限制”撰写。至少包含：

1. 验证表：期望/实测计数、时间、误差与判定。
2. 调度对照图：serial、paired、double。
3. IC 带宽曲线及平台期分析。
4. 阵列规模与流量/吞吐变化图。
5. Roofline 图和 PE 时序天花板解释。
6. Buffer 不变结果及其实现原因。
7. 可复现命令、源码版本与未建模因素。

完成标准：独立对账全部通过，实验数据可复现，至少能依据数据回答“请求并发与计算重叠分别有何收益”和“增加带宽或阵列规模为何会遇到收益限制”。未找到充分证据的原因不得写成确定结论。

可用于项目描述的表述是“完成简化 NPU 时序模型的独立解析交叉验证及架构参数敏感性分析”。外部模型对比和真实硬件校准留作后续，不计入本阶段验收。
